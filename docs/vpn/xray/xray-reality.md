# Xray: VLESS + REALITY + 3x-ui и сайт на Caddy

На одном сервере настроим сайт с HTTPS и VPN. Для управления VPN установим панель 3x-ui, для сайта и сертификата - Caddy. Подключаться к VPN будем с Android через v2raytun.

Xray будет принимать подключения на порту 443: пользователей VPN обслуживать сам, а обычных посетителей сайта передавать Caddy. В настройках REALITY укажем собственный домен, на котором работает этот сайт.

Понадобится чистая Ubuntu 24.04 x64. В инструкции используется 3x-ui 3.11.0; в других версиях названия пунктов могут отличаться.

## 00. перед началом

Нужны VDS с Ubuntu 24.04, доступ по SSH и домен, направленный на IP сервера.

В командах и настройках ниже используются примеры:

| Что | Пример |
|---|---|
| IP сервера | `203.0.113.10` |
| Домен | `vpn.example.com` |

Замените `203.0.113.10` на IP своего сервера, а `vpn.example.com` - на свой домен во всех командах и полях ниже. Эти примеры не подходят для подключения.

Порт панели в примере - `2053`. Логин, пароль и путь страницы входа у каждого будут свои.

В настройках DNS создайте A-запись: укажите в ней IPv4-адрес своего VDS. Если для домена включено проксирование через CDN, выключите его.

В этой инструкции используем IPv4. Для выбранного имени домена не добавляйте AAAA-запись, а существующую удалите: браузеры и сервис выдачи сертификатов должны подключаться по IPv4.

Команды рассчитаны на чистый VDS, где SSH работает на порту 22. Выполняйте шаги по порядку. Если команда закончилась ошибкой, сначала разберитесь с ней, затем продолжайте.

## 01. подключиться к серверу

На компьютере с Windows откройте «Пуск», напишите `cmd` и нажмите Enter.

Введите:

```bat
ssh root@203.0.113.10
```

При первом подключении проверьте отпечаток ключа через кабинет или консоль провайдера, затем подтвердите его словом `yes`. Введите пароль VDS.

При вводе пароля символы не показываются. Введите его и нажмите Enter.

После подключения появится строка вида `root@...:~#`. Теперь команды из этого окна будут выполняться на сервере с Ubuntu. Когда потребуется вернуться к Windows, об этом будет сказано отдельно.

## 02. установить нужные программы

В окне с Ubuntu выполните:

```bash
apt-get update
apt-get install -y curl ca-certificates ufw nano
```

Первая команда обновляет список пакетов. Вторая устанавливает curl для скачивания файлов, сертификаты для проверки HTTPS-соединений, фаервол UFW и текстовый редактор nano.

Команды выполняйте по очереди. Следующую вводите, когда предыдущая закончила работу и снова появилась строка `root@...:~#`.

## 03. открыть нужные порты

Фаервол определяет, какие подключения сервер принимает из интернета. Разрешим вход по SSH, работу сайта и VPN. Остальные входящие подключения закроем.

В окне с Ubuntu выполните:

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

На вопрос о включении ответьте `y` и нажмите Enter.

| Порт | Зачем он нужен |
|---|---|
| 22 | Ваш вход по SSH и доступ к панели |
| 80 | Получение и продление сертификата сайта |
| 443 | Сайт и VPN |

Если у провайдера есть отдельный сетевой фаервол, разрешите эти три TCP-порта и в нём. Порт панели управления наружу не открываем.

## 04. установить панель 3x-ui

В окне с Ubuntu скачайте официальный установщик 3x-ui и запустите его:

```bash
curl -fL https://raw.githubusercontent.com/MHSanaei/3x-ui/v3.11.0/install.sh -o /tmp/install-3x-ui.sh
bash /tmp/install-3x-ui.sh v3.11.0
```

На вопросы установщика отвечайте так:

| Вопрос | Ответ |
|---|---|
| Database Selection | `1` - SQLite |
| Customize the Panel Port | `y` |
| Please set up the panel port | `2053` |
| SSL certificate setup method | `4` - Skip SSL |
| Bind the panel to 127.0.0.1 only? | `y` |

Сертификат панели здесь не нужен: к ней будем подключаться по защищённому SSH-туннелю. Сертификат для самого сайта получим ниже.

Сохраните логин, пароль, порт и WebBasePath, которые покажет установщик. WebBasePath - путь страницы входа в панель; он понадобится для адреса в браузере.

Если установщик сам выбрал другой порт, используйте его вместо `2053` в следующем шаге.

### Если логин и пароль не показали

Введите в Ubuntu:

```bash
x-ui
```

Выберите `7` - Reset Username & Password. Подтвердите действие буквой `y` и задайте свой логин и пароль.

На новой установке ответьте `n` на вопрос об отключении двухфакторной авторизации. Согласитесь на перезапуск панели. Затем нажмите Enter, чтобы вернуться в меню, и введите `0`, чтобы выйти.

Панель продолжит работать: `0` закрывает только консольное меню.

Порт и путь панели можно посмотреть командой:

```bash
x-ui settings
```

Нужны строки `port` и `webBasePath`. На предложение создать SSL-сертификат для IP ответьте `n`.

## 05. зайти в панель

На Windows откройте второе окно cmd. Первое окно с Ubuntu оставьте открытым, в нём продолжим настройку сервера.

Во втором окне выполните:

```bat
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:2053 root@203.0.113.10
```

Введите пароль сервера. После подключения приглашение вводить команды не появится. Оставьте это окно открытым: в нём работает туннель.

Эта команда создаёт SSH-туннель: защищённое соединение между вашим компьютером и панелью на сервере. Через него панель откроется в вашем браузере, хотя прямой доступ к ней из интернета закрыт.

В браузере введите:

`http://127.0.0.1:18080/ВАШ_ПУТЬ_ПАНЕЛИ/`

Вместо `/ВАШ_ПУТЬ_ПАНЕЛИ/` вставьте значение `webBasePath` из предыдущего шага. Например, если сервер показал `/abc123/`, адрес будет `http://127.0.0.1:18080/abc123/`.

Войдите со своим логином и паролем панели.

Окно с туннелем не закрывайте, пока работаете в панели. Его закрытие прекращает доступ к панели, но не останавливает VPN. После перезагрузки VDS эту команду потребуется запустить заново.

## 06. установить Caddy для сайта

Caddy показывает сайт посетителям и автоматически получает для него HTTPS-сертификат.

Вернитесь в первое окно с Ubuntu. Добавьте официальный источник пакетов Caddy:

```bash
apt-get install -y debian-keyring debian-archive-keyring apt-transport-https gnupg
curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/gpg.key | gpg --dearmor --yes -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -fsSL https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt -o /etc/apt/sources.list.d/caddy-stable.list
chmod 644 /usr/share/keyrings/caddy-stable-archive-keyring.gpg /etc/apt/sources.list.d/caddy-stable.list
```

Теперь установите Caddy из добавленного источника:

```bash
apt-get update
apt-get install -y caddy
```

Caddy запустится автоматически.

## 07. создать страницу сайта

В первом окне с Ubuntu создайте папку сайта:

```bash
mkdir -p /srv/www
```

Откройте файл будущей страницы в редакторе:

```bash
nano /srv/www/index.html
```

Вместо командной строки появится редактор nano. Вставьте в него этот текст:

```html
<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Мой сайт</title>
</head>
<body>
    <h1>Мой сайт</h1>
    <p>Добро пожаловать на мой сайт!</p>
</body>
</html>
```

Сохраните файл: нажмите Ctrl+O, затем Enter. Закройте редактор сочетанием Ctrl+X. Знак `+` означает, что клавиши нужно нажать вместе.

Когда снова появится командная строка, разрешите Caddy читать страницу:

```bash
chmod 755 /srv/www
chmod 644 /srv/www/index.html
```

Это простая страница для проверки. Позже её можно заменить своим сайтом или случайным шаблоном из последнего раздела.

## 08. настроить Caddy и HTTPS

В окне с Ubuntu откройте файл настроек:

```bash
nano /etc/caddy/Caddyfile
```

Удалите прежнее содержимое: нажимайте Ctrl+K, чтобы убирать строки, пока файл не станет пустым. Затем вставьте конфигурацию ниже. В трёх местах замените `vpn.example.com` своим доменом.

```caddyfile
{
    https_port 8444
    auto_https disable_redirects
    servers {
        protocols h1 h2
    }
}

http://vpn.example.com {
    bind 0.0.0.0
    redir https://vpn.example.com{uri} permanent
}

https://vpn.example.com {
    bind 127.0.0.1
    root * /srv/www
    file_server
    tls {
        issuer acme {
            dir https://acme-v02.api.letsencrypt.org/directory
            disable_tlsalpn_challenge
        }
    }
}
```

Сохраните файл: Ctrl+O, Enter. Выйдите из редактора: Ctrl+X.

Caddy будет показывать файлы из `/srv/www` и получать сертификат через порт 80. HTTPS будет работать внутри сервера на порту 8444. Подключения посетителей из интернета к нему передаст Xray, который настроим в следующем шаге.

Проверьте конфигурацию:

```bash
caddy validate --config /etc/caddy/Caddyfile
```

Если написано `Valid configuration`, примените настройки:

```bash
systemctl restart caddy
```

Подождите примерно минуту: Caddy начнёт получать сертификат Let’s Encrypt. Успех зависит от правильного DNS и доступности порта 80. Сообщение `Valid configuration` выше подтверждает только правильность настроек, а не получение сертификата.

Сайт пока может не открываться из интернета. Сначала настройте Xray в следующем шаге.

## 09. настроить VPN в панели

В панели 3x-ui откройте слева «Входящие» и нажмите «Создать подключение».

### «Основное»

| Поле | Значение |
|---|---|
| Примечание | `VLESS REALITY` |
| Протокол | `vless` |
| Адрес | Оставить пустым |
| Стратегия адреса для ссылок | `Пользовательская` |
| Пользовательский адрес для ссылок | `vpn.example.com` |
| Порт | `443` |

Остальное оставьте как было. «Отключить поток XTLS» должно остаться выключенным.

Пользовательский адрес будет попадать в ссылки подключения. Так в них окажется ваш домен вместо `localhost`.

### «Протокол»

Ничего не меняйте: «Расшифрование» и «Шифрование» - `none`. Fallback’и не добавляйте, ключи на этой вкладке не генерируйте.

### «Поток»

Транспорт - `RAW`. Остальные переключатели оставьте выключенными, TCP Masks не добавляйте.

### «Безопасность»

| Поле | Значение |
|---|---|
| Безопасность | `Reality` |
| Xver | `0` |
| uTLS | `chrome` |
| Цель | `127.0.0.1:8444` |
| SNI | `vpn.example.com` |
| SpiderX | `/` |

Ключи и Short IDs оставьте сгенерированными. Если поля ключей пустые, нажмите «Получить новый сертификат». Несмотря на название, эта кнопка создаёт ключи REALITY. Сертификатом сайта занимается Caddy.

Остальные поля не меняйте. Ограничения fallback оставьте пустыми. «Сниффинг» и «Расширенный шаблон» не меняйте.

Нажмите «Создать».

### Проверить сайт

Откройте в браузере `https://vpn.example.com`.

Должна открыться страница «Мой сайт» без ошибки сертификата. Если она не открылась, сначала проверьте адрес домена, доступность порта 80 и журнал Caddy. Команда для просмотра журнала есть в разделе «Если возникла ошибка». К подключению телефона переходите, когда сайт заработает.

## 10. добавить пользователя VPN

В панели 3x-ui откройте слева «Клиенты» и нажмите «Добавить клиентов».

На вкладке «Основные» заполните поля:

| Поле | Значение |
|---|---|
| Email | `client1` - имя профиля, настоящий почтовый ящик не требуется |
| Привязанные входящие | Выберите `VLESS REALITY` |
| Лимит трафика, IP, HWID | `0` - без ограничений |
| Срок действия | Пусто |
| Включить | Включено |

Остальное не меняйте.

На вкладке «Учетные данные» в поле Flow выберите `xtls-rprx-vision`. UUID и другие поля оставьте сгенерированными.

Вкладку «Ссылки» оставьте пустой. Она нужна для добавления внешних подписок, в этой настройке они не используются. Нажмите «Создать».

## 11. подключить Android

В панели у клиента `client1` откройте QR-код или скопируйте его VLESS-ссылку.

В ссылке после `@` должен быть ваш домен с портом `443`, например `vpn.example.com:443`. Сам пример `vpn.example.com` в рабочей ссылке оставаться не должен. Если указан `localhost`, вернитесь к пользовательскому адресу для ссылок в шаге 9 и скопируйте ссылку заново.

На телефоне:

- Откройте v2raytun
- Добавьте профиль через QR-код или импорт из буфера обмена
- Выберите добавленный профиль и включите подключение
- Разрешите создание VPN, если Android спросит
- Откройте несколько сайтов

В панели у `client1` должен расти счётчик трафика. Проверьте работу через Wi-Fi и мобильный интернет. Названия кнопок импорта зависят от версии v2raytun.

Если сайты открываются и счётчик трафика растёт, подключение работает. Это не гарантирует работу во всех сетях: отдельно проверьте Wi-Fi и мобильного оператора, которыми пользуетесь.

## 12. проверить запуск после перезагрузки

В окне с Ubuntu выполните:

```bash
reboot
```

SSH отключится. Подождите около минуты. Переподключите v2raytun и проверьте сайты. Затем отключите VPN и откройте свой сайт обычным браузером.

Чтобы снова попасть в панель, запустите SSH-туннель из шага 5.

Чтобы продолжить работу с командами на сервере, снова подключитесь из cmd:

```bat
ssh root@203.0.113.10
```

Не забудьте заменить IP из примера своим.

## Продление сертификата

Caddy автоматически продлевает сертификат до истечения срока. Для этого сервер должен работать, домен - указывать на VDS, а порт 80 - оставаться доступным из интернета.

Не удаляйте папку `/var/lib/caddy`: в ней хранятся сертификаты и данные их получения.

## Если возникла ошибка

Эти команды не нужны для обычной установки. Используйте их только для поиска причины.

| Что не работает | Что проверить |
|---|---|
| Не удаётся подключиться по SSH | IP и пароль VDS, доступность TCP 22 у провайдера |
| Панель не открывается | Работает ли окно SSH-туннеля, правильны ли порт и путь панели |
| Сайт не открывается | DNS домена, порты 80 и 443, журнал Caddy |
| Сайт работает, VPN нет | Привязку клиента к входящему, Flow, SNI и параметры импортированного профиля |

Журнал Caddy на Ubuntu:

```bash
journalctl -u caddy -n 50 --no-pager
```

Журнал панели на Ubuntu:

```bash
journalctl -u x-ui -n 50 --no-pager
```

Если SSH не установлен, через консоль провайдера установите `openssh-server` и запустите службу `ssh`. Если предупреждение SSH говорит о смене ключа сервера, сначала сверьте новый ключ через консоль провайдера; не отключайте проверку ключей.

## Необязательно: заменить страницу случайным сайтом

Вместо стартовой страницы можно поставить случайный шаблон из GFW4Fun/randomfakehtml. Caddy умеет показывать готовые HTML/CSS/JS-файлы.

Для выбора шаблона сохраним небольшой скрипт. После этого менять сайт можно будет одной командой.

Скрипт заменяет текущий сайт без резервной копии. Настройки VPN и Caddy, ключи и сертификаты останутся прежними.

В окне с Ubuntu установите программы для скачивания и копирования файлов:

```bash
apt-get install -y git rsync
```

Откройте новый файл:

```bash
nano /opt/change-site.sh
```

Вставьте в редактор скрипт целиком. Его строки не нужно выполнять вручную:

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 022
repo=/opt/randomfakehtml
if [ ! -d "$repo/.git" ]; then
    git clone --depth 1 --filter=blob:none --sparse https://github.com/GFW4Fun/randomfakehtml.git "$repo"
fi
template=$(
    git -C "$repo" ls-tree -r --name-only HEAD \
      | awk -F/ 'NF == 2 && $2 == "index.html" {print $1}' \
      | shuf -n 1
)
test -n "$template"
git -C "$repo" sparse-checkout set -- "$template"
test -s "$repo/$template/index.html"
rsync -a --delete --chmod=D755,F644 "$repo/$template/" /srv/www/
printf 'Выбран сайт: %s\n' "$template"
```

Сохраните файл: Ctrl+O, Enter. Выйдите: Ctrl+X.

Теперь запустите скрипт:

```bash
bash /opt/change-site.sh
```

Он скачает выбранный шаблон, проверит наличие `index.html` и скопирует его файлы в `/srv/www`. После завершения появится строка `Выбран сайт:` с названием шаблона.

Откройте сайт и нажмите Ctrl+F5 на компьютере. Caddy перезапускать не нужно. Чтобы выбрать другой шаблон, снова выполните `bash /opt/change-site.sh`. Случайный выбор может повторить прежний шаблон.

`--delete` удаляет из папки сайта файлы, которых нет в новом шаблоне: файлы разных сайтов не смешиваются. При повторном запуске шаблон выбирается из уже скачанной версии репозитория.

Это демонстрационные шаблоны. Тексты, ссылки, формы и внешние ресурсы могут потребовать правки. В этой настройке Caddy не исполняет PHP и не отправляет сообщения из контактных форм.

Перед публикацией проверьте лицензию выбранного шаблона, соблюдайте её условия и сохраните указание авторства, если она этого требует.
